# Sincronización de identidades del dispositivo — implementación local

**Contrato coordinado vigente:** `docs/v2/CHECADOR_V2_BIOMETRIC_ADMIN_CONTRACT_V1.1.md`. Esta nota describe el endpoint de sincronización y debe interpretarse conforme a V1.1.

`POST /api/v2/devices/station/identities/synchronize` se registra únicamente si `CHECADOR_IDENTITY_SYNC_ENABLED=1`. Requiere TLS y Device Auth (`X-Device-Id`, `X-Credential-Key`, `Authorization: Bearer ...`). Cuerpo JSON exclusivo: `{"request_id":"11111111-1111-4111-8111-111111111111"}`; UUID V4 en formato hexadecimal minúsculo. No se aceptan IDs de dispositivo, estación o trabajador desde el cuerpo. No requiere sesión ni PIN administrativo.

La API revalida credencial y grant biométrico ligado a esa credencial bajo bloqueo, además de estación física activa, mapeo canónico único y pertenencia canónica vigente del trabajador. Selecciona trabajadores activos de la estación sin consultar huellas. Conserva identidad actual inequívoca, crea UUID V4 solo para personas sin historial V2 en ningún dispositivo, e informa como conflicto los demás casos. No modifica identidades históricas. Cada inserción es verificada por readback y toda la solicitud, incluidos resultados parciales e idempotencia, confirma en una única transacción.

200: `{"request_id":"...","created":2,"preserved":1,"conflicts":1}`. La pareja dispositivo/request_id conserva el resultado confirmado; al repetir, devuelve exactamente ese resultado. La misma clave tras un cambio de estación devuelve 409 `IDEMPOTENCY_CONFLICT`. Entrada inválida: 400 `BAD_REQUEST`; credencial inválida/revocada: 401 `DEVICE_UNAUTHORIZED`; grant o estación inválida: 403 `DEVICE_SCOPE_DENIED`; método: 405; contenido: 415; error transaccional o dependencia: 503 `SYNC_UNAVAILABLE`. Ninguna respuesta incluye huellas, secretos o datos de otra estación.

La idempotencia durable comparte `op_rh_v2_device_operation_requests` con las mutaciones biométricas; su DDL único se describe en `CHECADOR_V2_DEVICE_OPERATION_REQUESTS_DDL_PROPOSAL.sql`. La tabla es propuesta y no se ha aplicado. No crear la antigua tabla `op_rh_v2_device_identity_sync_requests`. La ruta permanece desactivada por defecto. Las transacciones MariaDB y la operación con el Lector real requieren verificación; las pruebas aisladas no las sustituyen.
